# Issue Triage v0.2 Implementation Plan

> Executed inline (native) right after writing, at the user's request ("implement the next phase"). The user chose to start v0.2 before the two-week maintainer test (#40) finishes.

**Goal:** Ship the GitHub Action, weekly digest with themes, and search/Ask on top of the v0.1 engine.

**Spec:** `docs/superpowers/specs/2026-10-06-issue-triage-design.md` (§5.2 digest, §5.3 Ask, §7.4 themes, §9 Action).

**GitHub issues:** #41 Action, #25 themes, #28 digest, #20 search, #21 Ask, plus the Ask parts of #6 (question length) and #7 (alias lookup).

## Global Constraints

Same as v0.1 (Python 3.10, synchronous, no network in tests, sanitized posted text, never closes or edits issues, dry run by default, secrets only from env). New dependencies are not allowed: themes and keywords use NumPy and the standard library only.

## Tasks

1. **Keyword index + search (#20).** FTS5 table `issues_fts` kept in sync by triggers, built for existing index files. `triage/search.py`: `hybrid_search(store, embedder, query, limit=10, state=None, labels=None, since=None) -> list[Hit]` merging FTS5 bm25 rank and vector rank with reciprocal rank fusion (k=60); filters applied before ranking. CLI `triage search "query" [--state] [--label] [--since] [--limit]`.
   Tests: exact error string ranks first despite unrelated embedding; filters exclude; FTS index rebuilt for an index created before v0.2; query punctuation does not break FTS syntax.
2. **Shared JSON chat model.** `triage/llm.py`: `ChatModel(cfg, client=None, max_calls=None)` with `ask_json(system, prompt, valid) -> dict | None`, calls/token counters, budget, `usage_summary()`. `Confirmer` builds on it (behaviour unchanged).
3. **Ask (#21, #6).** `triage/ask.py`: `ask(store, embedder, chat, question) -> Answer(text, citations: list[Hit])`. Question 1–1000 characters (`AskError` otherwise). Top 15 hits sent as delimited untrusted data; JSON `{answer, citations: [int]}`; citations outside the retrieved set dropped. CLI `triage ask "question"`; ConfigError when no LLM configured.
4. **Themes (#25).** `triage/themes.py`: `cluster(vectors, threshold=0.75, min_size=3) -> list[np.ndarray]` greedy leader clustering over open issues (unclustered issues stay out); `keywords(texts, corpus, n=4)` distinctive words; optional LLM naming via ChatModel.
5. **Digest (#28).** `DigestConfig(enabled, target: issue|none, waiting_days=14, window_days=7, theme_threshold=0.75, min_theme_size=3)` replacing the raw `digest` dict (`discussion` rejected with a clear ConfigError until supported). `triage/digest.py`: `build_digest(store, model, cfg, now, namer=None) -> Digest` with sections new themes, growing themes (new issues this window vs the previous window — no stored state), most-wanted without maintainer reply, waiting on maintainers, likely duplicates still open; `render_digest(repo, digest, now) -> str` (sanitized titles). `GitHubClient.create_issue`. CLI `triage digest` prints in dry run, else opens the digest issue.
6. **GitHub Action (#41).** `action.yml` composite action: inputs `command` (dupes|digest), `issue-number`, `github-token`, `config`, `llm-api-key`; restores/saves the index and the fastembed model in the Actions cache (`FASTEMBED_CACHE_PATH`); output appended to the job summary. `docs/github-action.md` with the example workflow. Dogfood: `.github/workflows/triage.yml` in this repo (dry run). CI smoke job runs the action from the PR checkout in dry run.
